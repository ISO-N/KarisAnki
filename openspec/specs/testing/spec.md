# Testing Specification

## Purpose

定义 KarisAnki 自动化测试体系的可观察要求，使后端业务逻辑、前端交互、离线状态和部署行为共享同一套可验证契约，避免前后端实现或测试各走各的。

## Requirements

### Requirement: API 契约统一

系统 SHALL 维护一份可被后端和前端共同使用的机器可读 API 契约，覆盖认证、卡组、卡片、队列、会话、答题、统计、设置和导入接口。后端测试 SHALL 验证真实响应符合契约；前端测试 SHALL 使用同一契约验证请求路径、请求体、响应体、状态码和错误码。

#### Scenario: 后端响应符合契约

- **WHEN** 任一受支持 API 返回响应
- **THEN** 响应字段、枚举值、状态码和错误码符合共享契约

#### Scenario: 前端请求符合契约

- **WHEN** 前端调用任一受支持 API
- **THEN** 请求路径、查询参数、请求体字段和错误处理符合共享契约

### Requirement: 规格场景可追踪

系统 SHALL 将 `openspec/specs` 中每个 Requirement 的每个 Scenario 映射到至少一个自动化测试，并维护可验证的追踪关系。新增或修改规格场景时，缺失对应测试 SHALL 被视为验收失败。

#### Scenario: 全部场景有测试

- **WHEN** 对当前规格执行覆盖审计
- **THEN** 每个 Scenario 至少关联一个后端、前端或 E2E 测试

#### Scenario: 规格变更阻止缺失测试

- **WHEN** 规格新增或修改行为场景且没有对应测试
- **THEN** 变更验收失败并列出缺失测试

### Requirement: 后端业务逻辑覆盖

系统 SHALL 使用单元测试和真实 PostgreSQL 集成测试验证调度状态机、队列生成与重学插入、答题幂等、统计口径、认证会话、导入原子性、软删除历史保留和时区语义。后端测试 SHALL NOT 仅依赖内存数据库模拟真实数据库约束。

#### Scenario: 调度状态机回归

- **WHEN** 新卡、复习、模糊重学、忘记重学或毕业流程发生
- **THEN** 测试验证 stage、重学计数、到期日和队列位置与规格一致

#### Scenario: 幂等与冲突语义

- **WHEN** 相同 `clientAnswerId` 重复提交、状态版本过期或批量部分冲突
- **THEN** 测试验证不会重复记账、冲突条目逐项返回且已接受条目不被重放

#### Scenario: 历史与统计口径

- **WHEN** 卡片或卡组被删除、重置或重命名
- **THEN** 测试验证当前流程移除正确、历史答题事件保留且统计口径不变

### Requirement: 前端行为覆盖

系统 SHALL 使用组件测试验证认证表单、卡组和卡片管理、导入预览编辑、设置、统计展示、复习状态机、评分键盘操作、Markdown/LaTeX 渲染和安全过滤。前端测试 SHALL 使用真实浏览器能力覆盖本地存储、IndexedDB、网络状态、主题、可访问性和响应式布局。

#### Scenario: 复习状态机完整

- **WHEN** 用户从正面查看答案、评分、离场并进入下一张
- **THEN** 组件测试验证状态转换、进度更新、重复提交防护和完成状态

#### Scenario: 前端交互与视觉契约

- **WHEN** 表单校验失败、破坏性操作、长内容、移动端或 `prefers-reduced-motion` 生效
- **THEN** 测试验证可见反馈、确认流程、无溢出、触控目标、键盘焦点和降级动效

#### Scenario: 不安全内容不执行

- **WHEN** 卡片内容包含 HTML、脚本、Markdown 或 LaTeX
- **THEN** 测试验证 Markdown 和 LaTeX 正常渲染且任意 HTML 或脚本不会执行

### Requirement: 跨层状态一致性

系统 SHALL 使用共享调度向量和全栈流程验证后端状态机与前端本地队列、outbox、会话恢复和缓存失效保持一致。前端本地进度模拟 SHALL 以后端确认结果为最终权威，冲突时 SHALL 按服务端状态恢复。

#### Scenario: 本地队列与后端一致

- **WHEN** 同一学习或重学场景在前端本地模拟并提交后端
- **THEN** 测试验证本地下一张、重学插入位置和完成状态与后端结果一致

#### Scenario: 离线同步恢复一致

- **WHEN** 离线评分、刷新页面、网络恢复或服务端状态冲突
- **THEN** 测试验证 outbox 不丢失、已确认评分不重复提交、冲突后重新获取服务端队列

#### Scenario: 缓存不掩盖服务端权威

- **WHEN** 客户端有缓存且后台响应返回最新数据、401 或网络错误
- **THEN** 测试验证缓存渲染不会让 401 失效登录态，也不会让网络错误清除登录态

### Requirement: 全栈流程覆盖

系统 SHALL 提供全栈 E2E 测试，从浏览器真实调用同域 API 并连接 PostgreSQL，覆盖注册登录、卡组卡片管理、学习复习、统计、设置和导入。E2E 测试 SHALL 验证用户可见流程而不是只验证接口。

#### Scenario: 核心学习闭环

- **WHEN** 用户注册、创建卡组和卡片、完成学习并查看统计
- **THEN** E2E 验证页面、API 和数据库状态同步更新且刷新后不重复记账

#### Scenario: 弱网全流程

- **WHEN** 用户加载会话快照后断网评分，再恢复网络
- **THEN** E2E 验证离线评分保留、自动同步成功且服务端状态正确

### Requirement: 部署与 CI 门禁

系统 SHALL 在 CI 中运行后端测试、前端测试、前端构建、全栈 E2E 和单容器 smoke 测试。发布流程 SHALL 在测试或构建失败时停止，单镜像 SHALL 验证前端代理到同容器后端，且任一进程退出时容器退出。

#### Scenario: 发布前置检查

- **WHEN** `master` 分支收到 push
- **THEN** CI 先运行完整测试、构建和 smoke 检查，失败则 SHALL NOT 发布镜像

#### Scenario: 单容器行为

- **WHEN** 构建单镜像并启动
- **THEN** smoke 测试验证 `:3000` 的 `/api/*` 请求转发到同容器后端 `:8080`，且任一进程退出后容器退出
