## Context

当前 `cards` 只有 `front`、`back` 和调度相关字段；JSON 导入只接受 `front`、`back`，卡片 API 也只返回这两个内容字段。复习页把 `front` 作为 Markdown 渲染，没有音标或发音入口。项目是自托管 Java/PostgreSQL 后端加 Next.js 前端，已有 Flyway 迁移、OpenAPI 契约、前端 IndexedDB 离线会话缓存。

用户希望发音范围扩展到任意卡片正面，但只针对中文和英文；音标仍只服务于单个英文单词卡。

## Goals / Non-Goals

**Goals:**

- 为单个英文单词卡提供可持久化的美式 IPA 音标。
- 后端本地生成音标，不依赖外部词典 API 或第三方音频服务。
- 任意正面内容只要识别为中文或英文，就能在复习页提供发音按钮。
- 中文使用 `zh-CN`、英文使用 `en-US`，中英文混排按连续同语言片段分段朗读。
- 发音仅按钮触发，不自动播放。

**Non-Goals:**

- 不引入通用卡片类型或卡片模板系统。
- 不为英文短语、中文内容或其他语言生成音标。
- 不处理除中文和英文以外的语言；不引入手动语言标记。
- 不存储音频文件，也不使用外部 TTS 服务。

## Decisions

### 1. 后端内置本地词典并持久化 IPA

选择把 CMUdict 数据放在后端资源中，由后端生成 `phonetic` 并写入 `cards`。原因是批量补齐、离线会话、卡片列表和跨设备展示都能保持一致，且不会把约 4.7MB 的词典打进前端首屏包。

替代方案：

- 前端内置词典：实现导入和补全时需要逐卡回写，已有卡批量补齐效率差，离线一致性也弱。
- 外部词典 API：能拿到真实音频和更完整音标，但依赖网络、免费接口有速率限制，不符合本地路线。

### 2. `cards` 增加可空 `phonetic` 字段

只增加一个可空文本列，不新增卡片类型。只有单个英文单词卡会写入值，其余卡片保留 `NULL`。

API 形状为增量兼容：

```text
CardResponse
  + phonetic: string | null

POST /api/decks/{deckId}/cards/pronunciation/backfill
  -> { updated, unchanged, missing, notWord }
```

导入、创建和编辑请求不需要客户端传 `phonetic`，由后端统一计算，避免客户端篡改或依赖前端词典版本。

### 3. 音标识别限定为单个英文单词

后端发音服务负责：

- 规范化 `front`：去除 Markdown 强调、代码标记、链接和图片语法，去掉首尾空白和装饰标点。
- 只接受一个英文单词：允许字母、撇号和连字符，例如 `apple`、`children`、`don't`、`e-mail`。
- 精确查本地字典；查不到就返回 `NULL`，不做规则猜测，避免错误音标。

CMUdict 是美式英语数据，默认只支持美音。字典主条目优先，暂不处理多发音选择。

### 4. 前端负责中英文识别和分段 TTS

发音能力不依赖 `phonetic`，因此短语、中文句子和普通 Markdown 卡片也能播放。前端新增发音辅助模块：

- 从 Markdown `front` 提取可朗读的纯文本。
- 按 Unicode 脚本分段：连续 CJK 文本为 `zh-CN`，连续 Latin 文本为 `en-US`。
- 只有清理后的文本包含 CJK 或 Latin 且不包含其他书写系统时才显示发音按钮。
- 点击按钮后按分段顺序创建 `SpeechSynthesisUtterance`，每个片段设置对应 `lang`，并取消前一次播放。

中英文混排不会强制用一种 voice，而是由浏览器按片段语言选择语音。

替代方案：

- 后端持久化 `speech_lang`：需要增加字段、迁移和语言检测逻辑，但对当前卡片场景收益不高。
- 手动语言标记：更准确，但增加卡组或卡片设置 UI，属于后续增强。
- 外部语言检测库：对短单词和短语也不稳定，反而增加依赖和误判。

### 5. 批量补齐作为已有卡片的入口

卡组详情页增加“补齐音标”操作。后端在一个事务内读取卡组活跃卡片，只更新 `phonetic IS NULL` 且正面匹配单词的卡片，返回更新、已存在、未识别和无需处理数量。该操作不修改卡片内容、调度状态或进度。

## Risks / Trade-offs

- 脚本级语言识别会把纯 Latin 的法语、德语等误判为英文，也会把包含日文汉字的文本误判为中文 → 当前用户场景主要是中英文卡片，后续需要更严格语言判断时可增加语言检测或手动语言标记。
- CMUdict 可能缺少专业词、生僻词或特殊变形 → 查不到时保持无音标，不猜测；后续可增加手动音标覆盖。
- 浏览器 TTS 音质和可用性因设备、浏览器而异 → 以 `lang` 属性为约束，不支持时隐藏按钮；音标展示不受影响。
- 旧前端缓存或旧离线会话中的 `Card` 对象没有 `phonetic` → 前端读取时用 `card.phonetic ?? null` 归一化，兼容旧缓存。
- 词典资源会增大后端制品体积 → 生成精简 IPA 资源文件并延迟加载，避免在应用启动时无条件占用内存。
- 大卡组批量补齐可能耗时 → 一次加载卡组活跃卡，单次事务完成，不逐张发起额外查询。

## Migration Plan

1. 新增 `V3__add_card_phonetic.sql`，为 `cards` 增加可空 `phonetic TEXT`。
2. 新增后端词典资源和 `PronunciationService`，再让创建、更新、导入和补齐流程使用。
3. 更新 API、OpenAPI 和前端类型，前端对缺失字段做兼容。
4. 部署时 Flyway 自动应用迁移；旧数据不会被破坏，补齐操作负责回填已有卡片。
5. 回滚时保留新列即可，API 和前端对缺失 `phonetic` 字段仍可正常工作。
