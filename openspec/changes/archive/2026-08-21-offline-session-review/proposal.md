## Why

KarisAnki 当前学习流程完全依赖在线逐卡请求：先拉队列，再逐张 GET 卡片，每次答题后还要重新计算并传输完整队列。弱网或短时断网时，用户会长时间卡在提交状态，甚至出现答案已在服务端记账但客户端报错重试、随后遇到 `stateVersion` 冲突的情况。作为闪卡应用，学习场景天然需要能容忍断续网络。

## What Changes

- 新增学习会话快照接口，一次返回当前学习/复习队列及队列中卡片的完整内容，避免逐卡 GET。
- 学习页改为基于会话快照工作；快照写入浏览器 IndexedDB，当前会话可在弱网或短时离线时继续复习。
- 答题请求增加客户端幂等键 `clientAnswerId`；服务端对重复请求去重并返回当前会话结果，保证重试不重复记账。
- 答题响应携带下一张卡或会话更新信息，在线学习不再每答一张卡请求一次队列和卡片。
- 客户端新增 outbox 机制：离线评分先写入本地待同步队列，恢复网络后按幂等键自动同步。
- API 层增加超时、网络错误分类和安全的 GET 重试；POST 不盲目自动重试，只允许幂等请求重试。
- 认证状态区分“网络不可达”和“会话失效”：网络失败保留本地用户状态并显示离线提示，只有明确 401 才清除登录态并跳转登录页。
- 同步冲突时，客户端下载最新会话并提示用户继续，而不是把本地状态当作最终结果。
- 不实现完整 PWA 或离线管理功能；本次离线范围限定为“页面已加载后，当前学习会话可继续完成”。

## Capabilities

### New Capabilities

- `offline-session`: 学习会话快照、IndexedDB 会话存储、离线答题 outbox、幂等同步、冲突恢复和弱网状态提示。

### Modified Capabilities

- `study-scheduling`: 队列生命周期从“服务端不持久化且每次刷新重新生成”扩展为“服务端仍不持久化，但活动会话可生成客户端快照并在离线答题后同步”；答题需要支持幂等去重。
- `account-auth`: 网络错误不得被视为会话失效；只有明确认证失败（401）才清除本地用户状态。

## Impact

- 后端新增或调整接口：`GET /api/decks/{deckId}/session`、`POST /api/answer`，并调整 `QueueService`、`AnswerService`、相关 DTO。
- 数据库新增 Flyway 迁移，用于持久化答题幂等键或去重记录，确保重放请求不会重复写入答题事件。
- 前端调整 `api.ts`、`auth-context.tsx`、`require-auth.tsx`、`study-session.tsx`，并新增会话快照/outbox/同步模块。
- 学习页协议从逐卡请求改为会话式同步；卡组管理、统计、设置等页面仍保持在线。
- 不引入外部离线同步服务；使用浏览器原生 IndexedDB 和现有同域 API。
