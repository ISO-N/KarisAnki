## Why

用户导入的卡片目前只有正面和背面，学习时正面没有发音入口；英语单词卡也看不到音标。我们希望任意卡片的正面都能在中英文场景下提供按钮播放，并让英语单词卡额外展示美式 IPA，同时不影响其他语言或普通 Markdown 卡片。

## What Changes

- 为 `cards` 增加可空 `phonetic` 字段，仅单个英文单词卡保存 IPA，其他卡片保持 `NULL`。
- 后端内置本地英语发音词典（CMUdict）和 ARPAbet 到 IPA 转换，不依赖外部词典 API 或音频服务。
- 新建、编辑、导入卡片时自动生成 `phonetic`；识别规则为“清理 Markdown 后只包含一个英文单词”。
- 为已有卡片增加批量补齐音标能力，通过卡组详情页操作触发。
- 复习正面为任意可识别的中文或英文卡片提供发音按钮，不限于单个单词。
- 发音使用浏览器 `SpeechSynthesisUtterance`：中文使用 `zh-CN`，英文使用 `en-US`，中英文混排时按语言分段朗读。
- 发音仅由用户点击按钮触发，不自动播放；其他语言或浏览器不支持语音合成时不显示按钮。
- `Card` API 返回新增的可空 `phonetic` 字段，字段为向后兼容的增量变更。
- 不引入卡片类型系统、不要求所有卡片具备音标、不存储音频文件。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `decks-cards`: 卡片数据模型增加可空音标；JSON 导入、新建和编辑卡片时自动生成英语单词音标；已有卡片支持批量补齐；复习正面展示音标，并为中文和英文卡片正面提供分段发音按钮。

## Impact

- 后端：`Card` 实体、Flyway 迁移、`CardService`、新增 `PronunciationService`、卡片与导入 DTO、OpenAPI 契约。
- 前端：`Card` 类型与 API 契约、复习卡片组件、正面语言识别与分段 TTS 模块、卡组详情页补齐音标入口、i18n 文案和组件测试。
- 数据：数据库新增可空 `phonetic` 列；后端资源中增加本地 CMUdict 数据。
- 测试：后端新增发音识别、IPA 转换、导入/编辑/补齐接口测试；前端新增音标展示、中英文播放、混排分段和不支持 TTS 的测试。
- 兼容性：API 新增字段不破坏现有客户端；未识别为中文或英文的卡片不显示发音按钮，非单词卡不显示音标。
